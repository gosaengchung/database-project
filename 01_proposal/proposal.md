# 픽로그(Picklog): 주식 스터디를 위한 분석 기록·복기 서비스

> 데이터베이스 학기 프로젝트 1차 기획안 · 2026년 10월 9일

## 1. 프로젝트 개요

**픽로그**는 관심 종목의 주가와 재무 정보를 살펴보고, 자신의 목표 주가·예상 기간·판단 근거를 저장해 스터디원과 공유하는 웹 서비스다. 전망의 확인일이 지나면 실제 주가와 비교하고, 그때의 판단이 왜 맞거나 틀렸는지 복기한다.

이 프로젝트의 목적은 매매 기능을 만드는 것이 아니라 **투자 정보를 읽는 과정과 투자 판단의 결과를 하나의 데이터베이스로 연결**하는 것이다. 초기에는 국내 상장주식과 소규모 주식 스터디를 대상으로 구현한다.


## 2. 해결하려는 문제와 주요 사용자

주식 스터디에서는 MTS로 가격을 보고, 재무제표를 찾고, 영상·기사·리포트를 공유한 뒤 메신저나 개인 메모에 의견을 남기곤 한다. 하지만 시간이 지나면 **당시 어떤 수치와 자료를 보고 얼마를 예상했는지**, 그리고 **예상 기간이 끝난 후 실제 결과는 어땠는지**를 한 번에 확인하기 어렵다. 이는 현재 참여 중인 스터디를 관찰하며 세운 문제 가설이며, 회원 조사로 검증할 예정이다.

주요 사용자는 ① 여러 관심 종목을 추적하는 개인 투자자, ② 자신의 투자 가설을 기록하고 싶은 스터디 회원, ③ 회원별 관점과 근거를 비교하며 토론을 운영하는 스터디 구성원이다.


## 3. 기존 서비스·콘텐츠 비교 및 시장 가설

공식 서비스 설명을 기준으로 비교했다. 아래의 ‘프로젝트 기회’는 기존 서비스에 해당 기능이 전혀 없다는 뜻이 아니라, **픽로그가 집중해 검증할 사용 흐름**을 뜻한다.

| 비교 대상 | 확인한 기능·특성 | 픽로그의 프로젝트 기회 |
|---|---|---|
| 토스증권(MTS) | 주식 관련 뉴스·공시의 AI 요약, 시장 일정, 투자 의견을 나누는 커뮤니티를 안내한다.[1] | 스터디원이 제시한 특정 목표 가격과 판단 근거를 작성 시점에 묶고, 예정일에 그 기록을 꺼내 복기하는 흐름을 설계한다. |
| 증권플러스(금융정보·거래 서비스) | 종목별 주가, 뉴스, 공시, 주주 커뮤니티, 종목 분석을 한 화면에서 제공한다.[2] | 여러 정보 중 사용자가 *실제로 판단에 채택한 근거*를 전망과 연결하고 이후 결과와 비교한다. |
| 투자 영상·콘텐츠 플랫폼 | 유튜브는 영상을 재생목록이나 ‘나중에 볼 동영상’으로 저장할 수 있다.[3] | 시청한 자료의 링크와 핵심 주장, 해당 자료를 바탕으로 세운 종목 전망을 함께 기록한다. 영상 자체는 수집하지 않는다. |

**시장 가설:** 정보 조회와 의견 공유 기능은 이미 널리 제공된다. 소규모 스터디에서는 여기에 *분석 당시의 근거 보존 → 일정 기간 후 결과 확인 → 토론과 복기*를 연결하는 도구가 유용할 수 있다. 실제 수요와 우선순위는 회원 인터뷰 및 시제품 사용으로 확인한다.


## 4. 서비스 운영 방식과 비즈니스 모델

초기 서비스는 개인 관심 종목·전망 기록과 소규모 스터디 공유를 제공한다. 사용자는 관심 종목을 추가하고 재무 정보를 확인한 뒤, 목표 주가와 기간을 직접 정한다. 다른 회원은 공개된 스터디 분석을 읽고 의견을 남길 수 있다. 비즈니스 모델은 현재 단계에선 고려하지 않는다.

추후 고려할 기능
1. 투자성향 기록 및 투자 성향에 따른 카테고리화
2. 투자 분석 리포트 밑에 관련 종목들 정보 및 링크 연결해두기

한계점
1. 현재는 모든 기업을 불러오는 데에 문제가 있으므로 스터디원이 기업 요청 시 기업들을 추가하는 식의 제한이 있음
2. 화면 구성 및 시스템 플로우에 대한 설계가 부족함
3. 데이터 API 연결 이후 batch로 데이터를 어떻게 불러올지 연구가 필요함 (실시간 데이터 불러오기가 여의치 않다면 ec2서버로 30분 내지는 1시간마다 자동 코드 실행으로 업데이트를 고려)

## 5. 핵심 기능과 사용 흐름

1. **로그인·관심 종목:** 회원을 구분하고 개인 관심 목록을 저장·조회한다.
2. **종목·재무 정보:** 날짜별 종가와 공시된 기간별 재무 수치를 보여준다. 조회 가능한 EPS를 표시하고, 기준 주가와 같은 기준의 EPS가 있을 때 PER을 계산한다.
3. **분석·전망 작성:** 종목별 분석 내용을 작성하고 작성일, 당시 기준 주가, 목표 주가, 확인 예정일을 저장한다. 사용자가 미래 EPS와 적용 PER을 입력한 경우 `예상 주가 = 예상 EPS × 적용 PER`을 계산해 목표가를 세울 때 참고한다.
4. **근거 자료 연결:** 재무 수치, 기사, 영상, 리포트, 개인 의견을 제목·URL·메모 형태로 전망에 연결한다. 외부 콘텐츠의 본문이나 영상 파일은 저장하지 않는다.
5. **스터디 공유:** 분석을 지정한 스터디에 공유하고 댓글로 다른 회원의 해석을 남긴다.
6. **확인 일정·복기:** 전망의 확인 예정일을 목록·달력에서 확인한다. 확인일이 휴장일이면 그 이후 첫 거래일의 종가를 사용해 목표가와 비교하고 복기 메모를 남긴다.
7. **분석 통계:** 완료된 전망의 실제 주가 변화율, 목표가 오차, 분석 횟수 등을 종목별·사용자별로 집계한다.

예를 들어 한 회원이 A사에 대해 ‘오늘 종가 50,000원, 6개월 뒤 목표가 65,000원’을 기록하고, 예상 EPS와 적용 PER 및 참고 영상 링크를 근거로 남긴다. 예정일 이후에는 실제 종가와 목표가의 차이를 확인하고, 실적 예상과 밸류에이션 가정 중 어느 부분을 다시 봐야 할지 복기한다.

**성과 지표의 해석:** 목표가 오차(`|실제 종가 − 목표가| / 기준 주가`)는 전망의 가격 차이를 보여준다. 실제 가격 변화율(`(실제 종가 − 기준 주가) / 기준 주가`)도 함께 표시한다. 이는 매매 수익률이나 투자 능력을 단정하는 지표로 사용하지 않는다.

## 6. 예상 테이블 구성 및 데이터 구조

PostgreSQL 관계형 데이터베이스를 사용하고, 현재는 아래 **13개 테이블**을 예상한다. 실제 컬럼·테이블은 ERD 작성과 사용자 조사 후 조정한다.

| 구분 | 테이블 | 주요 컬럼 예시 | 저장 목적 |
|---|---|---|---|
| 회원 | `users` | `user_id`(PK), `email`, `nickname`, `created_at` | 회원 식별 및 로그인 |
| 종목 | `stocks` | `stock_id`(PK), `ticker`(UNIQUE), `company_name`, `market` | 종목 공통 정보 |
| 관심 | `watchlists` | `watchlist_id`(PK), `user_id`(FK), `name` | 회원별 관심 목록 |
| 관심 | `watchlist_stocks` | `watchlist_id`(FK), `stock_id`(FK), `added_at` | 관심 목록과 종목의 다대다 관계 |
| 시장 데이터 | `stock_prices` | `stock_id`(FK), `trade_date`, `close_price`, `source` | 날짜별 종가; 종목·거래일 중복 방지 |
| 재무 데이터 | `financial_statements` | `statement_id`(PK), `stock_id`(FK), `period_end`, `report_type`, `revenue`, `net_income`, `eps`, `published_at`, `source` | 공시 기간·공개 시점별 재무 수치 |
| 스터디 | `study_groups` | `group_id`(PK), `name`, `created_by`(FK) | 스터디 그룹 |
| 스터디 | `group_members` | `group_id`(FK), `user_id`(FK), `role`, `joined_at` | 그룹과 회원의 다대다 관계 |
| 분석 | `analyses` | `analysis_id`(PK), `user_id`(FK), `stock_id`(FK), `group_id`(FK, 선택), `title`, `body`, `created_at` | 개인 또는 공유 종목 분석 |
| 전망 | `forecasts` | `forecast_id`(PK), `analysis_id`(FK), `recorded_at`, `base_price`, `target_price`, `target_date`, `expected_eps`, `assumed_per` | 작성 당시의 가격·기간·평가 가정 보존 |
| 근거 | `forecast_evidence` | `evidence_id`(PK), `forecast_id`(FK), `evidence_type`, `title`, `url`, `note`, `recorded_at` | 전망과 연결된 근거·출처 |
| 복기 | `forecast_reviews` | `review_id`(PK), `forecast_id`(FK), `actual_trade_date`, `actual_close_price`, `review_note`, `reviewed_at` | 확인 후의 결과와 복기 내용 |
| 토론 | `comments` | `comment_id`(PK), `analysis_id`(FK), `user_id`(FK), `body`, `created_at` | 스터디 분석 댓글 |

주요 관계는 **회원–관심 목록–종목**, **회원–스터디 그룹**, **회원–종목 분석–전망–근거·복기**, **종목–날짜별 주가·기간별 재무정보**다. `stock_prices`의 종목·거래일 조합과 `group_members`의 그룹·회원 조합에는 고유 제약을 둔다.

전망의 `base_price`, `expected_eps`, `assumed_per`는 **작성 당시 값**으로 보존한다. 이후 시장 가격이나 공시 수치가 바뀌어도 그때의 판단을 재현하기 위해서다. 특히 재무제표는 공시 후 정정될 수 있으므로 공개일과 출처를 관리한다.[4] 목표가·기준가 등 전망 핵심 값은 작성 후 덮어쓰지 않고, 변경된 전망은 새 기록으로 남기는 방안을 우선 검토한다.

## 7. 데이터 확보 및 구현 범위

초기에는 국내 종목 몇 개의 종목 정보·일별 종가·연간 재무 수치를 샘플 데이터 또는 허용된 파일 형태로 입력해 DB와 화면을 구현한다. 이후 금융감독원 OpenDART의 재무정보 API와 한국거래소의 일별 시세 API를 연동 가능한 후보로 검토한다.[4][5] 주가를 사용자에게 재배포하거나 서비스를 수익화하는 단계에서는 시세 데이터의 이용 조건을 별도로 확인한다.[6]

EPS는 **공시·데이터 출처에서 제공한 값**을 우선 활용한다. 예상 EPS는 사용자가 직접 입력하는 별도 가정이다. EPS의 기간이 서로 다르거나 0 이하인 경우, PER을 무리하게 계산하지 않고 기준 기간을 표시하거나 산출 불가로 처리한다. 실시간 시세와 자동 주가 예측 모델은 1차 구현 범위에 포함하지 않는다.

## 8. 소비자 조사와 개선 계획

현재 참여하는 주식 스터디 회원을 대상으로, 개발 전에 짧은 인터뷰를 진행한다. ‘지금 어떤 앱과 메모 방식으로 종목을 분석하는지’, ‘과거 의견을 다시 찾을 때 무엇이 어려운지’, ‘목표가와 확인일을 실제로 기록할 의사가 있는지’, ‘공유할 때 공개하고 싶지 않은 내용이 있는지’를 묻는다. 조사 전 단계이므로 회원 수요나 유료 결제 의사를 확인된 결과로 표현하지 않는다.

기본 기능을 만든 뒤에는 회원에게 실제 관심 종목 하나를 골라 **정보 확인 → 근거 첨부 → 전망 저장 → 다른 회원의 분석 확인**을 해 보게 한다. 작성 완료 여부, 입력에 걸리는 시간, 어려웠던 항목, 다시 사용하고 싶은 이유를 기록하고 개선 우선순위를 정한다. 목표일이 아직 오지 않았더라도, 과거 시점의 샘플 데이터로 복기 화면을 사용해 볼 수 있다. 테스트 과정에서 수집한 의견은 화면 설계와 테이블 구조에 반영한다.

## 9. 향후 구현 계획

| 단계 | 작업 및 확인 결과 |
|---|---|
| 1. 조사·설계 | 스터디 회원 인터뷰, 기능 우선순위, ERD 및 데이터 사전 작성 |
| 2. 데이터베이스 구축 | 13개 예상 테이블 중 핵심 관계 구현, PK·FK·중복 제약, 샘플 데이터 적재 |
| 3. 핵심 화면 | 로그인, 관심 종목, 종목 정보, 분석·전망·근거 입력 |
| 4. 스터디·복기 | 그룹 공유·댓글, 확인일 조회, 실제 종가 비교·복기 작성 |
| 5. 분석·개선 | 종목별·회원별 통계, 스터디 회원 사용 평가, 개선 사항 반영 |
| 6. 확장 검토 | 재무·시세 데이터 정기 갱신과 구독형 기능의 필요성 검토 |

**최종 목표:** 스터디원이 과거의 종목 분석을 다시 열어 당시 근거와 전망을 확인하고, 정해 둔 기간의 결과를 바탕으로 다음 분석을 개선할 수 있는 데이터베이스 기반 서비스를 구현한다.
